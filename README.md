# Common Ground

A disaster community-response platform for county and city emergency management, NGOs and states: resident damage and needs reporting, staff review, needs sharing with partners, public "Find help", missions and dispatch, a field app, FEMA declaration support, a CJIS enclave, ICS/EOC functions and AI assistance.

The product name is configuration (`PRODUCT_NAME`, ADM-03). "Common Ground" is the current working name.

**Status:** layer 1 (platform foundations) built, tested and approved 2026-10-12; layer 2 (resident intake) in progress. See `docs/plans/layer-2-status.md`, `docs/plans/layer-1-report.md` and `docs/traceability.md`. Build order follows SCL-14, one layer at a time; `CLAUDE.md` has the rules for resuming work.

## Start the stack

Requirements: Docker Desktop (Compose v2), Node 24 (`.nvmrc`), pnpm 10 (`corepack enable`). On Windows read [Windows (Docker Desktop)](#windows-docker-desktop) first.

```sh
scripts/init-env.sh          # writes .env with random local secrets (never committed)
docker compose up -d --wait  # builds images, starts every service, waits for health
```

The first `up` builds seven images and pulls six more; 10–20 minutes on a laptop is normal. `--wait` returns 0 once every service is healthy and the one-shot jobs (`migrate`, `keys-init`, `seed`, `seed-load`) have finished; `docker compose ps -a` shows the state at any time. The worker then provisions the nine synthetic organizations (sign-in realms, cast accounts) for another minute or two; `docker compose logs -f worker` shows it, and the test suites wait for it on their own.

Then open:

| URL                        | What                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| https://localhost/         | Resident app (English/Spanish). Accept Caddy's local certificate once, or trust it: `docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt .` |
| https://localhost/console/ | Staff console shell                                                                                                                                          |
| https://localhost/api/meta | API metadata; `/api/health/ready` lists dependency health                                                                                                    |
| https://localhost/auth/    | Keycloak (admin `cg-admin`, password in `.env`)                                                                                                              |
| http://localhost:8025      | Mailpit: every email the system sends                                                                                                                        |
| http://localhost:15672     | RabbitMQ management (`cg`, password in `.env`)                                                                                                               |
| http://localhost:9001      | MinIO console (`cg-local`, password in `.env`)                                                                                                               |

### Report damage as a resident

Open `https://localhost/county/westwind` (the root forwards there; `DEFAULT_TENANT` and `DEFAULT_EVENT` in `.env` change it). The flow asks one question at a time from the published graph, keeps answers on the device encrypted, works offline until it can send, and ends with a reference number such as `KXMR-4827`. Other entry points: `…/westwind/kiosk` (assisted entry by a helper, cleared from the device when done), `…/westwind/resume` (continue a paused report with its code), `/county/my-report` (reference number + the phone or email given → one-time code → status, consent, corrections, withdrawal; one-time codes to email land in Mailpit at `http://localhost:8025`). Photos upload straight to object storage through `https://objects.localhost` (trust the same local CA; browsers resolve `*.localhost` themselves).

## Text and call the county (simulator)

Without Twilio, the API plays the phone on synthetic data. Text the exercise county's number (`+13145550100`) from any number:

```sh
curl -sk https://localhost/api/webhooks/simulator/sms -H 'content-type: application/json' \
  -d '{"from":"+13145550199","to":"+13145550100","body":"DAMAGE"}'
# → {"replies":["Westwind County Emergency Mgmt: You're signed up …","… Is anyone in danger right now?\n1 Yes …"]}
```

Reply with the numbers (`2`, `1`, …), `BACK`, `SKIP`, `HELP`, `STOP`, or `DAÑOS` for Spanish; `SEND` at the end returns the reference code. A call starts with `{"from":"+13145550199","to":"+13145550100","step":"start"}` on `/api/webhooks/simulator/voice` and continues with `step` from the answer plus `digits` or `speech`. Texts the worker sends (confirmations, one-time codes) go to the in-process simulator and are recorded in `cg.message`. To use real numbers set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `WEBHOOK_PUBLIC_BASE` in `.env`, add the county's verified number to `cg.channel_number`, and point Twilio's webhooks at `/api/webhooks/twilio/sms`, `/voice` and `/status` through a secured tunnel (`docs/06`).

### Review reports as staff

Sign in as `priya.assessment@example.org` (`county`). **Review queue** lists reports with need signals first (unsafe, no shelter tonight, medical, displaced), then the oldest; filters cover event, state, verification, channel, flags and a reference number. A report opens to its answers grouped as the resident saw them, photos (links only for roles with the evidence category, blurred faces and plates when a detector is configured), needs, consent and the version history. Decisions (approve, reject, needs information, duplicate, supersede, reopen), the verification level and the FEMA degree of damage each ask for confirmation and a reason; the FEMA matrix next to the form is the official wording (DEC-03). A helper cannot approve a report they entered (guardrail G4). **Intake setup** shows each open event's resident link, kiosk link, text keywords and a QR code to print, and the question-graph versions: a new draft must pass the reading-level and tone rules before it can be published. **Assisted report** opens the kiosk flow for an event in a new tab. **AI use register** is the read-only list of every AI feature, its provider and its human checkpoint.

The CJIS enclave (`cjis-*` services) starts on its own internal network. It has no published ports on purpose: `docker compose exec cjis-api wget -qO- http://127.0.0.1:8080/health/ready`.

Maps (SCL-13) are opt-in because the first build downloads the Missouri OpenStreetMap extract: set `COMPOSE_PROFILES=maps` in `.env` for the geocoder and run `docker compose --profile maps-build run --rm tiles-build` once for vector tiles.

Behind a corporate proxy that inspects TLS, pass its CA to the builds: `docker compose build --build-arg HTTPS_PROXY=... ` and `--secret id=extra_ca,src=/path/ca.pem` (see `infra/node/Dockerfile`).

### Windows (Docker Desktop)

Docker Desktop runs the stack in WSL 2 (Settings → General → _Use the WSL 2 based engine_, on by default). Pick one of two ways to work.

**Recommended: work inside WSL 2.** The shell scripts, pnpm and every test then run unchanged, and builds are several times faster than from a Windows folder.

1. In PowerShell once: `wsl --install -d Ubuntu` (reboot if asked). In Docker Desktop → Settings → Resources → _WSL integration_, enable Ubuntu and Apply.
2. Open the Ubuntu terminal and clone inside the Linux file system (your home directory, not `/mnt/c/...`):

   ```sh
   git clone https://github.com/Mennelabs/EOC-Application.git ~/common-ground
   cd ~/common-ground
   scripts/init-env.sh
   docker compose up -d --wait
   ```

3. For the checks, install Node 24 in Ubuntu (nodejs.org → Download → Linux, or `nvm install 24`), then `corepack enable && pnpm install`.
4. Windows browsers reach the stack at the same URLs (https://localhost/ and so on).

**PowerShell only.** The stack runs the same; the shell scripts (`backup.sh`, `restore.sh`, the drills) and `pnpm test:e2e` need the WSL or Git Bash shell.

```powershell
git clone https://github.com/Mennelabs/EOC-Application.git
cd EOC-Application
.\scripts\init-env.ps1        # blocked by the execution policy? powershell -ExecutionPolicy Bypass -File scripts\init-env.ps1
docker compose up -d --wait
```

For the checks install Node 24 LTS from nodejs.org (the installer adds corepack), then `corepack enable` and `pnpm install` in the repository.

**Trusting the local certificate (optional).** Browsers warn once about Caddy's local CA. To trust it in Edge and Chrome: `docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt .` then `certutil -addstore -user Root root.crt` (Firefox keeps its own store: Settings → Certificates → Import).

**When it does not start**

- `required variable PRODUCT_NAME is missing a value`: `.env` is missing; run the init script in the repository folder.
- A clone made before `.gitattributes` existed may hold CRLF line endings. Symptoms: `db`, `cjis-db` or `keys-init` exit at once with `/bin/sh^M: bad interpreter`, `set: illegal option -` or `: not found`. Fix, in the repository folder (`.env` is untracked and survives):

  ```powershell
  git config core.autocrlf false
  git rm -r --cached -q .
  git reset --hard
  docker compose down -v
  docker compose up -d --wait
  ```

- Ports 80 and 443 must be free for the gateway; `bind: An attempt was made to access a socket in a way forbidden by its access permissions` means another program or a Hyper-V reservation holds one. Find the holder with `netstat -ano | findstr ":443 "` then `tasklist /FI "PID eq <pid>"`; IIS (_World Wide Web Publishing Service_) and VMware Workstation's shared VMs are the usual ones. The development ports (5432, 5672, 15672, 9000, 9001, 8200, 8081, 8025) can be moved in `.env` with `DB_PORT`, `QUEUE_PORT`, `QUEUE_UI_PORT`, `OBJECTS_PORT`, `OBJECTS_UI_PORT`, `KEYS_PORT`, `IDP_PORT` and `MAIL_UI_PORT`; `netsh interface ipv4 show excludedportrange protocol=tcp` lists Hyper-V's reserved ranges.
- The stack wants about 6 GB of memory. Raise WSL 2's share in `%UserProfile%\.wslconfig` (`[wsl2]` then `memory=8GB`), then `wsl --shutdown` and restart Docker Desktop.
- `container common-ground-<service>-1 exited (<code>)` or a service that never becomes healthy: `docker compose ps -a` shows which one and `docker compose logs <service>` why.
- `docker compose ps -a` and `docker compose logs --no-color > compose-logs.txt` are what to share when it still fails.

## Seed data

The `seed` service writes the synthetic county (tenants, areas, parcels, facilities, personnel, resident reports) to the `seed_data` volume; `seed-load` loads the WESTWIND hierarchy, shipped role templates and the console cast into the database and hands provisioning (identity realms, invitations) to the worker. Both run on every `up` and are no-ops when already loaded. To write the JSON locally instead:

```sh
pnpm seed                      # -> tools/seed/out/
pnpm seed -- --seed 7 --reports 5000
```

Everything it produces is invented and marked `synthetic: true`. Loading it into the database arrives with the layer-1 schema. **Only synthetic or exercise data ever goes into this stack (SCL-12).**

## Run the checks

```sh
pnpm install
pnpm lint              # eslint + prettier
pnpm typecheck
pnpm check:product-name   # ADM-03: product name never hardcoded
pnpm test              # unit tests (vitest)
pnpm test:integration  # against the running stack (STACK_URL, COMPOSE_FILES to override)
pnpm test:e2e          # Playwright + axe accessibility and the onboarding journey (npx playwright install chromium first)
scripts/backup.sh && scripts/restore.sh backups/<stamp>   # NFR-05; drills in tests/drills/
DATABASE_MIGRATOR_URL=... pnpm --filter @cg/db check:migrations 3   # newest migrations up, down, up; dictionary and RLS checks (SEC-05/11)
pnpm --filter @cg/intake lint:strings   # INT-08: reading-grade table and tone findings for the question graph
pnpm --filter @cg/ai evaluate           # AIG-08: evaluation report for the AI provider (default: fake)
pnpm --filter @cg/db check:migrations 1 # drill the newest migration up, down and up against the compose database (needs DATABASE_MIGRATOR_URL)
pnpm reqindex          # regenerate docs/requirements-index.md after editing docs/0*
```

CI (`.github/workflows/ci.yml`) runs all of these plus Semgrep, Trivy dependency/secret/container scans and an SBOM. Image scans fail the build on fixed HIGH/CRITICAL findings in our layers and the Alpine packages; findings inside the upstream Caddy binary are reported without failing, because every Caddy release lags its Go libraries, and are cleared by bumping the pinned Caddy image (`compose.yaml`, `infra/web/Dockerfile`).
