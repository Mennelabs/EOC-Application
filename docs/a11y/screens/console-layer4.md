Open: check 2 (screen reader) for these screens.

Layer 6, task J (2026-10-15): the **situation map** gains outages (a point where the facility is known, otherwise listed with "Place not known") and tract shading chosen in a radio group ("Shade the tracts by": damaged housing units, reports per 100 homes, share below poverty, limited-English households). Each shading names its source and as-of time, has a legend that says every class in words (and, for coverage, "Heavy dashed outline: under-reported", so the flag is not colour alone), and a table by tract with the same values (counts under 11 read "Unknown or fewer than 11", EQ-13). The radios are 24 px with their labels as part of the target (WCAG 2.5.8). With the map shown, point markers can sit closer than 24 px at a zoom: that falls under WCAG 2.5.8's **Equivalent** exception, since every marker's item is in the table beside the map; the journey runs every other axe rule on the markers and the target-size rule on everything else (`expectNoViolations(page, { mapMarkers: true })`). Evidence: `tests/e2e/console-l6.spec.ts` (situation map journey, desktop + phone), `services/api/test/equity.db.test.ts` (area layers).

Axe evidence (2026-10-16): the layer-4 journey opens the dispatch board, missions and the roster; board replay, shelters, volunteer reception, the net control log, messages to the field, badges, reminders and field devices are opened one by one in `tests/e2e/console-screens.spec.ts` with axe on desktop and phone and no sideways scroll on the phone. The reminders step sets one two days overdue and checks it reads "Overdue" in words with the ⚠ symbol hidden from screen readers (FR-09.05), then completes it. With no permission, the roster, net control and messages screens keep their heading above the reason (they showed the reason alone before).

Volunteer reception, sign-up by QR (FL:FR-20, 2026-10-16): the code is an image with a text alternative and its address printed beside it, so it is never the only way in. The waiting list and the open codes are captioned tables; each row's buttons name the desk code ("Register K7P3", "Decline K7P3"), and "Register" moves focus to the prefilled name field with a sentence above the form naming the request being completed. The waiver checkbox says in words whether the waiver was accepted on the phone. `tests/e2e/console-screens.spec.ts` (FL:FR-20) runs axe on the screen with a code open and with a request waiting, on desktop and phone.

Staging check-in code (2026-10-16, FLD-03): the roster screen gains a "Staging check-in code" region. The QR code is an image whose alternative text spells the code out letter by letter, and the code is also printed beside it in large monospace letters, so the sign works for people who type it and for screen readers (AC-13C, WCAG 1.1.1). "Print" prints only that region. "Make a new code" says in a status message that the old code no longer works. The badge print view now shows the badge code as a QR image as well, with the same spelled-out alternative text, beside the code in text. Evidence: `tests/e2e/console-screens.spec.ts` (roster with axe, desktop and phone) and `tests/e2e/console-l4.spec.ts` (badges with axe).

Reports from the field (2026-10-16, FLD-11): the dispatch board gains a "Reports from the field" heading and a table captioned "Site status and resources seen, newest first". Each report reads in words: the site and what was seen there, or the kind of resource and its place. A report with no pin says "No pin". Each "Mark noted" button names its report, and the result is announced in the board's status message. The count sits in the board's summary list. In `tests/e2e/console-l4.spec.ts`, axe passes with the table shown, on desktop and phone.

Board map layers (2026-10-16, DSP-01): the optional board map now has three more layers: needs (a diamond marked "N"), road closures (a square marked "X") and field reports (a diamond marked "R"). Each layer has its own toggle button with a pressed state, and each marker has a name in words, for example "Need: food water, no mission yet" or "Road Old Mill Rd: impassable". A layer is never colour alone. The map's name says the lists below show the same items, and every layer is also a table. In `tests/e2e/console-l4.spec.ts`, the map is opened, a layer is toggled, and axe passes, on desktop and phone.

Equipment used (2026-10-16, FL:FR-19): a mission page shows an "Equipment used" heading and a table whose caption gives the total hours. Each row reads the equipment, its unit number or what "other" was, the day and the hours. With nothing logged, it says "None logged." Roles that do not read equipment do not see the section. In `tests/e2e/console-l4.spec.ts`, axe passes on the mission page with the section, on desktop and phone.

Searched layer (2026-10-16, FL:FR-01): the situation map gains a "Searched" layer button with a pressed state. Its markers are circles marked "SR", named "Searched" or "Searched, outside only", and its table lists the same marks with the code painted on the building. Road closures now also include roads a crew reported closed, impassable or down to one lane. In `tests/e2e/console-l4.spec.ts`, axe passes on the situation map with the new toggle, on desktop and phone.

Badge photos (2026-10-16, BRD:FR-13.01, FR-13.04): the personnel detail has a "Badge photo" section. Its file input is labelled "Take or upload a badge photo"; on a phone it offers the camera. Each image has a text alternative naming the person, and a pending one says it is waiting for approval. "Approve photo of <name>" and "Reject photo of <name>" are named buttons, and a refusal is announced as an alert. On the badge print view, the photo has the alternative "Photo of <name>", and the name and every other detail are printed in text beside it. In `tests/e2e/console-screens.spec.ts`, axe passes with a pending photo and the refusal shown, on desktop and phone.

Roster location (BRD:FR-03.05, 2026-10-16): the check-in table's Location column says in words whether sharing is off, the phone blocks location, the phone cannot get a position, the position is old (with its time) or recent; the board's team row adds "location blocked on N phones". Nothing relies on colour.

Health notices (FL:FR-06, 2026-10-16): one form with labelled fields, the Spanish part in a fieldset marked `lang="es"` with its legend in English; the notices table is captioned and every button names its notice ("Check reach of …", "Approve and publish …", "Lift …", "Withdraw …"); status and reach are words and counts. Approval and ending ask for a reason in the shared confirmation dialog. The screen is in the per-screen axe scan and in the FL:FR-06 journey, desktop and phone.

Mission intake addresses (BRD:FR-03.02, 2026-10-16): "Find the address" and "Find the address at these coordinates" are buttons; matches are a labelled list ("Addresses found") of buttons that name the address and whether it is the address of record or map data; what was chosen, or that nothing was found, is announced in a status line. Cross streets and coordinates are labelled fields with hints. Nothing changes focus on its own.
