Layer 6, task J (2026-10-15): the **situation map** gains outages (a point where the facility is known, otherwise listed with "Place not known") and tract shading chosen in a radio group ("Shade the tracts by": damaged housing units, reports per 100 homes, share below poverty, limited-English households). Each shading names its source and as-of time, has a legend that says every class in words (and, for coverage, "Heavy dashed outline: under-reported", so the flag is not colour alone), and a table by tract with the same values (counts under 11 read "Unknown or fewer than 11", EQ-13). The radios are 24 px with their labels as part of the target (WCAG 2.5.8). With the map shown, point markers can sit closer than 24 px at a zoom: that falls under WCAG 2.5.8's **Equivalent** exception, since every marker's item is in the table beside the map; the journey runs every other axe rule on the markers and the target-size rule on everything else (`expectNoViolations(page, { mapMarkers: true })`). Evidence: `tests/e2e/console-l6.spec.ts` (situation map journey, desktop + phone), `services/api/test/equity.db.test.ts` (area layers).

Axe evidence (2026-10-16): the layer-4 journey opens the dispatch board, missions and the roster; board replay, shelters, volunteer reception, the net control log, messages to the field, badges, reminders and field devices are opened one by one in `tests/e2e/console-screens.spec.ts` with axe on desktop and phone and no sideways scroll on the phone. The reminders step sets one two days overdue and checks it reads "Overdue" in words with the ⚠ symbol hidden from screen readers (FR-09.05), then completes it. With no permission, the roster, net control and messages screens keep their heading above the reason (they showed the reason alone before).

Staging check-in code (2026-10-16, FLD-03): the roster screen gains a "Staging check-in code" region. The QR code is an image whose alternative text spells the code out letter by letter, and the code is also printed beside it in large monospace letters, so the sign works for people who type it and for screen readers (AC-13C, WCAG 1.1.1). "Print" prints only that region. "Make a new code" says in a status message that the old code no longer works. The badge print view now shows the badge code as a QR image as well, with the same spelled-out alternative text, beside the code in text. Evidence: `tests/e2e/console-screens.spec.ts` (roster with axe, desktop and phone) and `tests/e2e/console-l4.spec.ts` (badges with axe).
