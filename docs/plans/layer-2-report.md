## What passed

- **Checks:** typecheck (every package and, new, every test suite), lint, ADM-03 product-name check; 167 unit tests (graph schema and branches, dialogue, string lints, AI redaction/prompt/filter/evaluation, templates and SMS segments, photo pipeline, resident storage/outbox/photos/state, Twilio signatures and TwiML); 37 database-backed API and worker cases run in CI against the compose database; the stack suites (layer 1: 21 cases, layer 2: 12 cases) against `docker compose up`; 30 end-to-end tests on desktop and phone with axe WCAG 2.2 AA on every screen reached; the k6 smoke profiles.
- **End to end, on clean volumes:** a web submission goes through the queue to the worker and comes back as a report with the same reference; the same Idempotency-Key replays the same code; with the queue stopped the submission is accepted and stored, then filed when the queue returns; the lookup answers the same way for a wrong contact, sends a one-time code by email for the right one, and the code opens the resident's own report and nothing else; a reviewer claims and approves with confirmation and a reason, the decision and the pre-decision version are kept, the resident sees the state in plain words and never the reviewer's notes; the helper who entered an assisted report is refused on it (403) and a role without the review grant gets nothing (404); a resident correction after approval sends the report back for review with the approved snapshot kept; verification level and FEMA degree are reviewer decisions; zero and unknown stay apart; a renter's unknowns are kept; needs file with the report, consent defaults to none and a withdrawal is kept; a danger answer is a flag in the queue and nothing dispatch-like exists; a whole report by text through the simulator with an MMS photo ends in a reference code, the photo is processed with EXIF stripped and stays restricted, the confirmation text is recorded as sent, STOP opts the number out.

- **Migrations:** the whole chain runs on a fresh database (the CI stack job proves it on every push) and the newest twelve run down and up again on PostGIS; 48 tables, 634 dictionary rows, no undocumented or stale column, RLS forced on every tenant table.
- **Gates claimed:** GATE-02 (the acceptance cases above), GATE-03 for the resident flow on automated evidence with the per-screen records (manual screen-reader pass open, below), GATE-04 (public routes reach only intake, drafts, uploads, extraction, lookup and the resident's own report; every staff route needs a grant), GATE-05 (idempotent submissions, duplicate flags for people, versions), GATE-06 (submission and lookup without staff credentials), GATE-08 for the fake provider (confirmation, scope, injection cases, manual fallback).

## What did not pass, or is not yet proven

Nothing is red at the end of the layer. The honest gaps:

1. **Screen-reader passes (GATE-03).** Every check that automation can prove is recorded in `docs/a11y/screens/`; the NVDA and VoiceOver passes need a person. Until then GATE-03 rests on automated evidence and keyboard journeys.
2. **Load at the SCL-03 target.** The k6 profiles exist and the smoke profile runs in CI; the full profiles (28 submissions per second sustained with bursts, 20,000 concurrent text sessions) need a host sized for them. No full-profile numbers are recorded yet.
3. **CI during the layer.** Runs 36–44 were red in turn: migration 0009 failed on a fresh database (the dictionary loader named columns later migrations add; fixed in `c55b2fe`), the resident review screen's definition lists failed axe and the progress line was not a status region (`1426105`), the pause-and-resume check pressed the resume screen's own Back on the phone project (`65944c8`), and the first run of the stack suite found five wrong assumptions in the tests themselves (`e77959d`). The run after `e77959d` is the one this report stands on; the status file records its number.
4. **Spanish and imagery.** Spanish ships as reviewed drafts marked as such; professional translation and community review (EQ-07) and community-reviewed imagery (EQ-04) are go-live gates, not code.
5. **Partials by design** (each with its layer in the traceability table): the blur detector and image-similarity duplicates (layer 7), server-side speech-to-text and real translation (paid providers), custom domains (cloud move), the map in intake and the geocoder (layer 3/4), needs-only entry without a report and partner delivery (layer 3), adding photos on the web to a report started by text, printed cards and wristbands (layer 4), IA-total exclusions and Public Assistance flags (layer 6), antivirus scanning of uploads (images are decoded and re-encoded instead).
6. **Reference codes are never recycled** and the objects host needs a DNS or hosts entry on custom hostnames (status file, known issues).

## Readings taken in the residents' favour (flagged for you)

The eight resolutions in `layer-2.md` §12 stand (lookup contact, danger flag, witness and organization records, pause codes, risk-based verification, photos before blurring, SMS keywords). The build added these:

1. **Self-review refusal is visible (G4).** A helper who tries to approve a report they entered gets a 403 with the reason, where every other missing grant stays a 404. The helper already holds the review grant and may read the record, so the refusal reveals nothing new and tells them why (FR-12.04, AC-12B).
2. **Access needs are health-adjacent.** The access-needs answers are hidden from the damage-assessment coordinator and shown only to the access-and-functional-needs roles (RULE-16, ACM-01, ADM-05), even though that coordinator sees contact details and free text.
3. **Zero and unknown.** Household size starts at one (a report is about a lived-in home); counts that can be zero (employees affected, units) accept zero and keep it apart from unknown (AC-10A, RULE-02).
4. **One confirmation per report.** A report started by text gets its confirmation in the dialogue, not a second time from the worker; a web report gets one text or email at most, only with the opt-in (CHN-04).
5. **Kiosk devices clear themselves** two minutes after a confirmation and on completion, announced first (ACC-41, CHN-07).
