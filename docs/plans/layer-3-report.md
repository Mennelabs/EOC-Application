## Readings taken in the residents' favour (flagged for you)

The eight resolutions in `layer-3.md` §12 stand (fixed minimum fields per service, immediate withdrawal with recall, confidential sites never leave the console, nothing public without a named approver and stale sites hidden, needs without a report need neither contact nor place, updates only to opted-in channels with the output filter, the page never says who is eligible, partner users are partner tenants' own accounts). The build added these:

1. **Protected categories come from the role template only.** Access needs reach a partner only through a template that carries the category (the shelter nurse), never through an agreement's category list, so a county cannot widen it by configuration (ADM-05).
2. **Withdrawal is same-transaction.** NED-05 allows an hour; the grant is revoked and the recall queued in the worker transaction that records the withdrawal.
3. **Partner reads are audited where the partner is.** Each read is in the partner tenant's log with the grant id and the categories read; the county's log shows what was granted and revoked. A county-side ledger of partner reads waits for the read-receipt work in layer 4.
4. **The media sheet does not refresh itself.** A timed refresh fails WCAG 2.2.1/3.2.5; the sheet carries its generation time and says a reload is the reader's choice.
5. **Reminders name no people.** The weekly contact digest and the site reminders carry agencies, sites and dates; names and numbers stay in the restricted registry.
6. **The needs-only flow confirms by the channel the resident gave**, with its own reference code and the NOSHARE keyword, so a resident who never filed a damage report can still stop sharing.
