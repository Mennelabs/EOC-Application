# Layer 3 status

The coordination record for layer 3 (needs board, partner sharing with consent, public "Find help"). Any session resumes from this file, not from chat. Update it in every commit that changes a task's state. Plan: [`layer-3.md`](layer-3.md). Decisions: [`../decisions.md`](../decisions.md). Layer 2 record: [`layer-2-status.md`](layer-2-status.md).

## Resume checklist

1. `pnpm install && pnpm typecheck && pnpm test && pnpm lint && pnpm check:product-name` green before new work.
2. Stack for integration work: `scripts/init-env.sh` (or `scripts\init-env.ps1`) then `docker compose up -d --wait`; `COMPOSE_PROFILES=maps` for the tiles and geocoder.
3. Pick the first task below that is not `done`, finish it to green, commit citing requirement IDs, update this file, push.
4. Every task A–J is `done` (2026-10-13). **Layer 3 approved by Adam on 2026-10-13** with the report's recommendations (`docs/decisions.md`); layers 2 and 3 merge into `main`; layer 4 continues in `layer-4-status.md`.

## Known issues and deferred items

- CI: the last run recorded here is the one on the layer's final commit; see the row at the end of this list.

- See `layer-3.md` §11 for deferred IDs and §12 for the readings taken in the residents' favour.
- Two text keywords are new (`NOSHARE`, and `SHELTER`/`REFUGIO` now answer with sites): approved by Adam for the carrier submission on 2026-10-13 (`docs/06`, `docs/decisions.md`).
- Partner reads are audited in the partner's tenant; the county's audit log shows grants, updates and revocations but not each partner read. A county-side read ledger (one row per partner read on the grant) is deferred to layer 4 with the field app's read receipts (DSP-06), since both need the same cross-tenant audit relay.
- The partner workspace browser journey (plan §9) ran once partner administrators were seeded (layer-4 task 0, decision 2026-10-13): `tests/e2e/console-l3.spec.ts` onboards a canteen coordinator through the canteen's own administrators and checks the consented sections, a claim and axe. Recall notices to a partner with no role holder now reach its administrators rather than its security contact.
- Reminders (task H) email in English only; a per-account language for staff is not modelled yet (the resident side is bilingual). The weekly contact digest and the site reminders name agencies, sites and dates, never contact names or numbers (SEC-18).
- The outside-link check is a HEAD request (GET after 403/405) with a five-second timeout from the worker container; a site that blocks automated requests reads as broken until the owner looks.
- Email replies to staff updates are not captured by the system (task E): the email asks the resident to reply, and the reply lands in the county's own mailbox. Capturing inbound mail needs an inbound mail route (a paid service decision for Adam).
- Partner actions on the board (claim, release, done) run inside the county's RLS context through `request.txAs`, after the grant is verified in the partner's own context and only for that one need; they are audited in the county's log with the partner account as actor. Keep `txAs` to grant-covered records (documented on the decorator).
