## What passed

- **Checks:** typecheck, lint, the ADM-03 product-name check, 239 unit tests, the 18 database-backed suites run one file at a time against the compose database in CI (122 cases), the Android debug build (expo prebuild and Gradle), Semgrep, the dependency, secret and container scans and the SBOM.
- **Stack suite (layer 4):** the field lead checks in by the event code and their positions reach dispatch and not the field; a help alert reaches a dispatcher's open stream; a command batch sent twice applies once and a stale command gets the current record; an agency dispatcher sees only their own agency; a net-control position lands on the team; a silent team turns overdue on the worker's own clock with one alert, and "we are OK" clears it; positions stop at check-out.
- **Migrations:** the chain runs on a fresh database on every push; 0040 runs up, down and up locally with no undocumented or stale column and row security forced on every tenant table.
- **Local browser smokes** of every new console and field screen against stubbed APIs: 0 axe violations and no horizontal scroll at 360 px (layer-4 status, tasks H–K).

## What did not pass, or is not yet proven

1. **The browser journeys and the field load profile against the stack** run after the stack suite in the same CI job. Their first complete run is the one this report closes on; see the status file for the result.
2. **Screen reader and on-device checks (GATE-03).** TalkBack, VoiceOver and NVDA passes, gloves, sunlight, real GPS and the camera need a person with a device (`docs/a11y/screens/console-layer4.md`, `field-app.md`).
3. **CI during the layer.** Found and fixed: migration 0037's rollback under forced row security (`ab47856`); a queue-down case racing the sweep (`a92453e`); the review screen confirming before the refetch (`78f6416`); a test drain decrypting the stack worker's messages (`8ebc32f`); Semgrep on an `Object.assign` of a follow-up's result (`5da0357`); a test leaving a volunteer on a seeded team (`5da0357`); the stale-site list filtered after its first page, a real PUB-03 bug (`9036398`); the stack suite's dispatcher signing in with a role that cannot read the board (`36da0e0`); and a real race in the audit chain since layer 1 (`cdbc089`, below).
4. **The audit chain race (BRD:FR-08.04).** An audit row's number was taken before the per-tenant chain lock, so two concurrent writers could chain in the opposite order to their numbers and verification reported a break with nothing tampered. Migration 0040 takes the number after the lock; a 40-writer test fails under the old trigger and passes under the new. A running database whose chain was already broken by the race keeps reporting it, which is the right behaviour; development and CI databases start fresh.
5. **Not built, and not deferred in the plan** (traceability notes): releasing a person's open assignments when they go off duty (AC-05C, waits on BRD:DEC-07); finding a resident record by phone and code or address and name (FL-02); consented document photos (FL-09); a photo and a QR image on the badge (the code prints as text); the ArcGIS/Survey123 file export and import (CON-17); the phone's map and the area map extracts; screenshot blocking and managed configuration (FLD-02); retention sweeps for the new categories and pruning of the change feed (SEC-13). Each is a small, separate task.
6. **Known issue:** the contacts list answers 500 when one row cannot be decrypted; the field records already withhold such a value per field. Querystring flags parsed with `z.coerce.boolean()` read `"false"` as true across the staff API; a follow-up task is queued.

## Readings taken in favour of safety and privacy (flagged for you)

The ten in `layer-4.md` §12 stand (exact position on a help alert, sharing stops at check-out, "arrived" never automatic, resident details leave the phone, wipe touches only the app, children's minimum data, background checks as a status, hours from check-in, skills only when recorded, badges readable without the QR). The build added:

1. **A partner-run county shelter:** the county sees the census the operator confirms (status and occupancy), not the households, which stay with the organization serving them (CON-16). Showing households would need a sharing agreement like the needs board's.
2. **The situation map rounds report and need points to about a kilometre** unless the role holds exact locations, and audits exact reads; confidential sites never appear.
3. **Voice-note drafts fill only structure, water inside and what was seen,** never the FEMA degree; a person decides.
4. **Child records keep one year** (retention `child_records`).
5. **Volunteer self-registration by QR was not built:** reception registers walk-ups, who then check in with the event code.
