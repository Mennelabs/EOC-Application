Written 2026-10-15 as a draft; **revised the same day with Adam's answers** (`docs/decisions.md`, interview of 2026-10-15; §14). Layer 7 starts after the partner self-posting work ([`partners-before-layer-7.md`](partners-before-layer-7.md)). Build order SCL-14 step 7. No feature here may decide eligibility, priority, damage category or dispatch on its own.

## 2. Ground rules every AI feature follows

1. **Providers stay pluggable (AIG-12, ADR-0025).** One internal interface each for language models, speech-to-text, translation and image analysis, plus a **damage classifier** interface (PHO-12) that OpenAI's vision model fills for now and a validated model can replace. **The provider is OpenAI for every function** (decided 2026-10-15) until a cloud provider is chosen with the first customer; its AIG-06 record carries Adam's statement that the Mennelabs OpenAI organization has zero data retention, with the agreement attached, and every tenant language still needs a passed evaluation (AIG-08). The key is the secret `OPENAI_API_KEY`. **Running systems never use the fake provider:** without a key the AI features are off and the non-AI paths run; the fake survives only as a test double in automated tests. Model names are configuration per feature, not code.
2. **Every output is recorded** (AIG-01, AI-03): feature, provider, model and version, prompt template version, latency, outcome, and what a person did with it (accepted, edited, rejected). Prompts and raw free text are not written to general logs (CMD-37, CMD-38, NFR-10); restricted content stays in encrypted columns under its retention category.
3. **Untrusted content is data** (AIG-02, CMD-11, AC-C10): resident text, photos, partner notes, retrieved pages and record content go to models only inside delimited data fields and never change instructions, tools or permissions. Model output is parsed against a fixed schema and validated on the server before anyone sees it (AIG-03, AI-08).
4. **Minimum context** (AI-02, CMD-35, AIG-05): a feature sends only the authorized fields it needs, with names, phone numbers, emails and exact addresses tokenized unless the task needs them (redaction gains names).
5. **Output filter** (AIG-07): every generated text passes `filterGeneratedText` (no eligibility, promises of aid, medical or legal advice, or another person's data) before display or sending.
6. **Health and fallback** (AIG-09, AI-10, SCL-06): each feature has a per-tenant correction or error rate over a rolling window (default: more than 30% of the last 50 outputs in a language corrected or rejected; photo agreement 5 points below average for any group); crossing it **alerts the tenant administrator and the feature keeps running** (decided 2026-10-15, a deviation from AIG-09's auto-disable). A provider failure or timeout still falls back to the non-AI path at once (AI-10). No spending cap (decided 2026-10-15); usage is recorded per tenant. Timeouts are per provider (BRD:INT-04).
7. **Labels** (AI-03, PHO-10, ACC-53): generated text is marked as drafted until a person saves it; machine translation is labelled; AI suggestions read "AI suggestion — not verified" everywhere.

## 3. The command window

**Contract (BRD:FR-C03, CMD-12).** The existing action catalog (`packages/authz/src/actions.ts`) becomes the command catalog by adding, per action: version, argument schema (zod), target and scoping rules, prerequisites, confirmation class (`none | one_tap | full_review | second_person`), side effects, idempotency behaviour, result schema and reversal policy (`undo_15_min | compensating | none`). Only catalogued actions can run; anything else is answered as unsupported, never as done.

**Execution path (NFR-11, CMD-21, CMD-23).** A command never touches the database directly. The executor calls **the same HTTP operations the console calls**, in process, with the requester's own credentials, execution id and expected record versions. Validation, authorization, locks (RULE-05), versions, idempotency and audit are therefore identical to the manual path. Authorization is checked when the plan is prepared and again at confirmation (AC-C05).

**Two ways in, one plan (CMD-03, CMD-05, CMD-20).** Deterministic shorthand (`/mission 20261009-003 status on_scene`, the Section 30.2 syntax, Spanish verbs as synonyms) is parsed without a model and works when AI is off. Natural language goes to the language model, which may only return a plan in the catalog's schema (intent, action names, arguments, references to resolve); the server resolves names to stable ids among authorized matches only (CMD-08, RULE-18), asks a focused question when there is more than one, resolves dates in the tenant's time zone and shows the interpretation (CMD-10).

**Plan, confirm, execute (BP-05, the state model).** Received → interpreted → clarification or prepared → awaiting confirmation → confirmed → revalidated → executing → succeeded, partially succeeded, failed or cancelled. A confirmation is bound to the plan's hash, the record versions, the user and the scope (FR-C05, AC-C04): any material change re-prepares and re-asks. Results are verified from the operation's own response and name what was drafted, saved, queued, sent, delivered or failed (CMD-26); a multi-step plan reports each step and never claims a rollback it cannot do (CMD-24, AC-C07).

**Recommended defaults (Section 30.2, BRD:DEC-16; behind configuration until Adam approves, §14 question 1).** Ctrl+K or Command+K, "/" outside text fields and an always-visible button, remappable, never over screen-reader keys. Rollout in four phases: (1) search, summaries and drafts; (2) reversible updates (notes, reminders, need claims); (3) assignments and status changes with confirmation; (4) approvals, priority, closure, bulk changes, outbound messages and administration. Confirmation: none for lookups and drafts, one tap for a single reversible change, the full review screen for every RULE-14 action, a second person for permission grants and messages to more than 500 recipients. Undo: 15 minutes for reversible internal changes; everything else through a compensating action, never a pretended recall (CMD-28, AC-C08). Batches: 50 records, up to 500 with a second confirmation, more as a scheduled bulk job; 30 consequential commands a minute per user. History: personal conversations 30 days, clearable, off on shared devices; the execution audit follows the 7-year default and cannot be cleared (RULE-15, CMD-36). Targets: shorthand under 1 s, interpretation under 2.5 s, confirmed execution under 2 s at the 95th percentile; 15 s timeout with an honest pending or failed state.

**Aliases (CMD-04, BRD:FR-18.05).** Personal aliases for lookups and drafts only; organization aliases by administrators, versioned and audited, never hiding a destructive or bulk action; the expansion is shown before anything consequential.

**Unsaved work and public users.** The console registers open drafts; a command touching a record with an open draft asks to keep, reconcile or discard (CMD-29, AC-C09). Residents get only the public coverage in Section 30.2: published resources, starting or resuming their own report, and their own status after verification (CMD-19, AC-C03).

**Accessibility (CMD-31–34, ACC-52).** A dialog with managed focus, a live region for progress and results that does not chatter, every clarification a labelled form control, typed equivalents for dictation (whose transcript is always reviewed before a consequential action, CMD-33), unsent text kept locally, and no automatic replay of queued consequential commands after reconnecting (CMD-34, AC-C12).

## 4. Scribe, voice and translation in the field (docs/04, Section 29.1)

- **Conversation scribe (FL-04, FL-18).** In the field app, with the survivor's spoken or tapped consent in their language (stored with the note), the app records while a visible "listening" indicator shows and the survivor can say stop; it never runs in the background. Audio goes to restricted, encrypted object storage; speech-to-text and the language model draft a structured note (needs heard, help given, follow-ups, referrals) that the worker reviews and confirms afterwards; **the audio is deleted when the note is confirmed** (`scribe_audio` retention, already seeded as on-confirm). Each tenant and each partner organization can turn it on or off; speech-to-text is OpenAI's transcription (decided 2026-10-15); extraction accuracy is measured per language and a crossed threshold alerts the administrator (AIG-09 as decided).
- **Where it never runs (FL-05, FL:FR-16, FL:FR-23, FL:FR-26).** It cannot be turned on for counseling or spiritual care; it is off by default for legal aid and anything involving a child; legal notes stay outside the shared record.
- **Voice commands (FL-07)** are command-window actions from the field app, always confirmed on screen before saving.
- **Shift hand-over (FL-12).** At check-out the worker gets a drafted summary of the shift's own records (what happened, what is still open), sourced and editable, which they confirm for the next shift.
- **Live translation (FL-14, FL:FR-24).** Machine translation between worker and survivor in the launch languages, labelled as such, with one tap to bring in a human interpreter through the interpreter queue; consent, legal and medical conversations always go to a human interpreter.
- **Server speech-to-text** for the scribe, field voice notes (FLD-09), voice commands and intake (INT-12) is OpenAI's transcription; the phone's and browser's own dictation stays as the offline and no-AI fallback.

## 5. Photo pre-sort (Section 12)

- **The severity suggestion (PHO-09, PHO-12 as decided 2026-10-15).** The damage classifier interface takes photos and home type and returns a suggested D05 class mapped to a FEMA degree or "cannot tell", a confidence and the visible features behind it (Section 29.2). **OpenAI's vision model fills it now** (Adam's decision, a deviation from PHO-12's purpose-trained model and the CLAUDE.md fixed decision); a model registry records which model and prompt version produced each suggestion so a validated classifier can replace it without code changes. PHO-13 is met from the review records: reviewer agreement by hazard, home type and income band, published per model version (Section 19); a group falling behind alerts the administrator.
- **The human decision (PHO-10, PHO-11, DCL:DEC-02).** When a suggestion exists, the review screen shows it labelled "AI suggestion — not verified", never to the resident; the reviewer sets the degree from the FEMA matrix, and the decision records the suggestion, the reviewer and whether they agreed (the columns exist).
- **Queue order (PHO-14):** need signals first (unsafe, no shelter, medical), AI severity only as a tie-break, so AI never pushes a vulnerable household down.
- **Detector (PHO-07):** OpenAI's vision model reports whether faces, plates, documents or house numbers are present and where. A missed face is a privacy leak and a general vision model's coordinates are not reliable enough to trust alone, so any photo it says contains sensitive content and cannot box precisely is blurred whole or kept restricted (reading 6).
- **Near-identical images (PHO-15):** a perceptual hash computed in the worker flags near-identical photos across reports for a person to review; reverse-image matching against stock photos waits for a provider that offers it.

## 6. Recommendations and resource discovery (docs/02 Section 23)

- **Facility registry (REC-01).** A per-tenant registry with the attributes docs/02 lists (square footage, ADA, generator or transfer switch, kitchen, showers, pet policy, parking, truck access, floodplain, MOU status, contacts, communities that use it), approved by county EM; owners update their own entries; the COAD proposes; a public self-registration form feeds an approval queue; owners are reminded every 12 months and stale entries are flagged. The seed's WESTWIND facilities move into it.
- **The engine (REC-02–12).** Rules and optimisation in `packages/reporting`, never a language model (REC-12): hard filters (no power and no generator, in a damage or flood zone, not accessible, not reachable), then a deterministic, explainable score with tenant-adjustable weights and documented defaults, sized by the tenant-editable planning factors (shelter square footage, showers, meals, POD types and 72-hour supplies, MARC needs). It answers with the top three and their reasons, the excluded sites and why, what would change the top pick, the age of every input with a stale warning (REC-10), and the equity check: coverage by tract income, renter share and language, flagging any high-need area left uncovered (REC-11). Shelters, feeding stops (REC-05/06, from partners' declared assets), PODs and walk-up points (REC-07/08, no-vehicle households from the ACS profile) and MARCs (REC-09). A named person accepts, edits or rejects, and the decision and reason are logged (REC-04). The language model may only word the explanation, and the explanation is checked against the computed reasons (every figure and site it names must be in them) before display.
- **Proactive discovery (REC-13, REC-14; Q-06 as decided 2026-10-15).** The first source is the partners themselves: services partner organizations post (built before this layer) appear immediately and feed the registry. On the tenant's schedule (weekly; daily during an active event) a worker job also reads the county's own sources (open-data portals, 211/HSDS feeds, with the outbound rules of ADR-0042) and runs **OpenAI web search** with place types and the county's area only, never personal data. It drafts each candidate with source links, fills what it can confirm, marks the rest unknown and pre-checks it against the registry criteria; candidates wait in the administrator's review queue, nothing is added, changed or removed without a decision, and rejected candidates are remembered unless something changes. A digest goes by email or in the console; during an active event a high-value candidate near unmet need is raised at once.

## 7. AI drafting that people approve

Situation reports and briefings (CMD-16, CON-06, FR-15.02, AC-15C): the existing template draft can be rewritten by the model from the computed facts only, each sentence citing its facts, labelled as drafted and still unapprovable until a person has read and saved it; a check refuses a draft that states a figure not in the facts (AI-04, AI-09, AI-12). The same pattern drafts PIO posts (PUB-12) and audio scripts for low-power radio and ARES/RACES nets (PUB-14; audio files from OpenAI text-to-speech), alert text sized for WEA (PUB-11), and Boxes 8 and 9 of Form 010-0-13 (DCL:DEC-14). Nothing goes public or official without its named approver (PUB-06, RULE-10).

## 12. Readings taken in favour of privacy and safety (flagged for Adam)

1. **Shorthand never needs a model**, so every command that can be written as shorthand works with AI off (CMD-05, AC-C12).
2. **The command executor uses the console's own operations** in process with the user's credentials, instead of a second implementation of each action (NFR-11): one place for validation, locks, versions and audit.
3. **A confirmation is bound to the plan's hash and record versions**; anything that changes re-asks (AC-C04, CMD-09).
4. **Scribe audio is deleted on confirmation, and a draft never confirmed expires** with the conversation retention (30 days), audio included; the note is the worker's to confirm, never auto-saved.
5. **Scribe consent is stored with the note in the survivor's language**; a survivor's "stop" ends recording at once and keeps nothing after it.
6. **The privacy blur fails closed:** a photo the vision model says contains a face, plate, document or house number that it cannot box precisely is blurred whole or stays restricted; severity suggestions are labelled, never shown to residents, never set the degree, and their agreement with reviewers is reported by group.
7. **The recommendation explanation is checked against the computed reasons** before display; one that names a site or figure the engine did not produce is refused (REC-12, AIG-07).
8. **Discovery never adds, changes or removes a facility without a person** (REC-13); web searches carry place types and the county's area only.
9. **Names join the redaction list** (AIG-05): the current redactor tokenizes contact details and street addresses but not names.
10. **Translated consequential commands get the full review screen** (CMD-32), even when the action would otherwise take one tap.
11. **Section 29 wins on dictation:** approved, always with review; the BRD's "if included" wording is superseded (Section 29.1).
12. **The scribe drafts only what was said** (layer-7 task H, AI-09): each drafted line carries the words it rests on, and a line whose words are not in the conversation is dropped before the worker sees it. Names, phone numbers, emails and street addresses are removed before the model sees the conversation and put back for the worker. A conversation that tries to instruct the model drafts nothing.
13. **The scribe's note is staff-facing**, so the public-text filter (AIG-07) marks a line that reads as a promise or advice for a second look rather than removing it: the worker is recording what was said, not telling a resident something new.
14. **A legal aid note is only ever its author's** (FL:FR-23); other notes are read by caseworkers once confirmed, each read audited. Shelter nurses and counselors have no scribe (FL:FR-16; health details belong in the restricted health note).
15. **AIG-09 for the scribe follows Adam's decision of alerts only**: the per-language correction rate comes from the confirmed notes the worker changed, through the existing AI health alerts; FL-18's automatic switch-off is not built.
16. **Machine translation keeps nothing and never decides** (FL-14, EQ-08): the words go to the provider for one turn and come back labelled; the record keeps the languages, outcome and model only. Consent, legal and medical conversations are refused by the server, not only hidden on the phone, and every role that may translate may also call an interpreter.
17. **Agreement by group (PHO-13 as decided):** "income band" is the poverty quintile of the report's census tract among the county's tracts (band 1 the highest poverty share), as the equity view ranks them; home type is conventional or manufactured, as the FEMA matrix splits them. A group is behind when it has at least 20 decisions and its agreement is more than 10 points under the model's overall agreement (tenant `ai.fairness`); unknown groups are shown but never alerted. A group behind raises an AI health alert (`fairness`), not a switch-off (AIG-09 as decided).
18. **A legal aid organization's referral responses share the status only** (FL:FR-23): accepted, declined, or done ("service given"). The note is neither stored nor shown to the referring organization, nor written into the county's audit; the organization keeps its own notes (the legal-aid scribe note is its author's alone). It applies to the legal aid attorney role and to any organization that sets `referrals.confidential_outcomes`.
19. **Resident dictation goes through the county's provider or not at all** (INT-12, AIG-06, AIG-10). The browser's speech recognition sends audio to Google (Chrome) or Apple (Safari) under no agreement with the county, so it is not used. The phone keyboard's own microphone stays the resident's choice. A clip recorded on the device goes to the provider's speech-to-text only where the register has `intake.transcription` on. Its words come back into the text box to change, nothing is stored, and the resident is told plainly that a computer writes the words down. The button is hidden when computer help is off.
20. **The register lists only what calls a provider** (AIG-01). `photo.quality` is retired: PHO-03's retake suggestion runs on the device before upload, so it works on a slow connection, and needs no AI. The provider's image analysis still returns quality notes alongside the sensitive regions, but nothing uses them. A reviewer-facing quality note would be a new feature, with its own register row.
21. **A resident's complaint about computer help is a fixed reason, with no words** (AIG-09). Where the intake shows answers read from the resident's words, or words written down from their voice, "This computer help got something wrong" offers four reasons: wrong answers, not my language, hard to understand, something else. The reason is kept on that help's AI output, once; nothing the resident types is sent, and their report is not changed. The public answer is the same whether or not there was such help, so ids cannot be probed. The health job raises a `complaints` alert when more than 10% of a feature's last 50 outputs in a language drew one (tenant `ai.health.complaintRate`), told and cleared like the others; never a switch-off (AIG-09 as decided).
22. **The approved time zone is the tenant's own, for showing and for typing** (BRD:FR-00.08). Times stay stored in UTC. The console shows every time on the county's clock (`cg.tenant.timezone`, through `/me`) with the zone named ("7:00 AM CDT"), whatever zone the browser or a liaison's laptop is in, and reads a typed date and time on that same clock, so what is typed is what is shown back. Across a daylight-saving change a wall time stays that wall time; a time in the hour skipped in spring moves forward by the hour, as clocks do, and a time in the repeated autumn hour is read as the first one. A device may date an entry made after the fact back, never more than five minutes ahead (AC-08A).
23. **Asking for peer support is private to the peer-support role** (FL-16). A worker's request holds only how to reach them (a call, a text or in person) and when (as soon as possible or after their shift), never words or a reason. Only the crisis-counselor template reads it, through the counseling category that comes with that template key (ADM-05 G7), so a county that grants the action to another role still shows nothing; the worker's lead, dispatch, coordinators and administrators never see it, and nothing about it reaches the board, roster, activity log or team messages. The phone number shown is the worker's own roster contact, and only when they asked for a call or a text. The request is audited like every write but the audit holds no how or when; each read by the peer-support role is audited as counseling data. A closed request is deleted after 30 days (`peer_support`, tenant-configurable); an open one never expires. The rest reminder appears on the phone once time on shift passes the county's `field.rest_after_hours` (12 hours unless set), or the person's own lower hours limit; it is a reminder, never a lock-out. The screen always shows the 988 line for someone in crisis now.
24. **A field report of how a site looks, or of a resource seen, is an observation for dispatch** (FLD-11). The quick report offers three kinds: a hazard (as before), how a site looks (open, open but limited, full, closed or damaged) and a resource the worker came across (water, food, fuel, a pharmacy or store open, power or charging, equipment, something else), each with the phone's position, photos and a note. A site report never changes the site's status of record, which stays with the site's lead (`site.confirm`, the census screen), so a passer-by cannot open, fill or close a shelter by tapping; dispatch sees the report on the board and marks it noted. A resource seen goes to dispatch, not into the county's facility review queue, since discovery candidates are buildings to qualify for operations, not supplies seen in passing. The place is a place or landmark, never a person (SEC-10, said on the screen). Reports are field records, counted from the day their event closes (SEC-13).
25. **A resupply request drafted at the reorder point is only a draft** (FL:FR-21, FL:FR-22). When stock of an item at a site reaches its reorder point, the site's one draft request gains that item with a suggested quantity: what went out in the last 24 hours plus enough to get back to the reorder point, less what is left. It is never sent on its own: a person checks the amounts, changes any, and sends it. An item already on a draft, or on a sent request not yet filled, is not asked for again, so one shortage is one request. Requests carry items and amounts only, never who received them, and no one is asked for ID to receive help (FL:FR-22). Like stock, they are equipment records that follow the core records they serve (SEC-13).
26. **A lost pet is matched by a person, not by the system** (FL:FR-08). For a lost report the system lists animals found or sheltered in the same event and of the same kind, ranked by the words their descriptions share, and shows those words; it never links them itself. A person confirms "This is the same pet", which links both records, and later marks the pet gone home, which marks both. A lost report cannot be matched to another lost report, a matched animal is not suggested again, and the owner is known by their reference code only. The shelter census counts animals sheltered now, by shelter and kind of animal.
27. **A canteen stop's allergen note is about the food, never about people** (FL:FR-17). A feeding crew's stop records where (a public place, never a household), when it arrived and left, how many meals went out, what is left on the truck, and an allergen note such as "chili contains peanuts" or "6 asked for gluten-free". The screen says plainly never to write who has an allergy, because a person's allergy is health information that the canteen record must not hold.
28. **An "approved photo" is approved by a second person** (BRD:FR-13.01). A badge photo taken at the desk or uploaded waits as pending; someone other than the person who took it approves or rejects it (ADM-05 G4, the same guardrail as approving your own finding). Only the approved photo is printed, and a badge request cannot name another image. The upload is re-encoded, which drops the photo's location and camera details. Photos are served through the API to roles that read the person, never from a storage link. A rejected photo is deleted; a replaced approved photo stays for the badges printed with it until the person's record is swept (SEC-13).
