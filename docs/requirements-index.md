## How to read this

- **Key**: the ID used in code, tests and commits. Three ID families collide across documents, so they carry a namespace prefix: `BRD:` (original BRD/FRD), `DCL:` (Section 20 declaration support + docs/05) and `FL:` (frontline-role features in docs/04). All other IDs are unique and stay bare. See finding C-01.
- **Class**: Must/Should/May as stated in docs/01–05. The original states P0/P1/P2: P0 and P1 are treated as **Must** (SCL-14 puts the whole release in scope; stricter rule wins). P2 items are resolved through the Section 29.1 approvals. Unprioritized system-wide rules (RULE, AI, ACC, CMD, GATE, acceptance cases) are Must (Section 29 preamble).
- **Layer**: SCL-14 build layer 1–8. `All` = cross-cutting, built first where it is first needed and re-tested in every layer. `Gov` = needs the government cloud. `Process` = compliance/organizational evidence, not code. `Deferred` = blocked on an open decision. `Trace` = business goal/feature group satisfied through its children. `Decision` = original decision register entry.
- **Source**: `file-prefix:line`, e.g. `00:506` = docs/00-original-BRD-FRD.txt line 506.
